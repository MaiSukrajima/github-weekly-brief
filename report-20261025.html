本周由 php2shell 一个漏洞主导：PoC、绕过、补丁、检测规则，以及大厂出的自查工具，五天之内全部到齐。

🐚
ikow/php2shell-poc

CVE-2026-109618 / 109619：PHP 预认证 RCE，影响 5.4.0–8.5.11 共 14 年的版本，本周全网工具的源头仓库。

Python ★ 1.7k
能怎么用

docker compose up -d 起 PHP-FPM + nginx + mod_php 三套靶场，再跑 poc/verify_*.py 逐条验证。5 条利用链开源 3 条：A 会话注入 + LFI、B var_destroy UAF 覆写 var_dump handler、C FPM serializer 错配触发 __destruct；D（mod_php 零依赖预认证）和 E（FPM 跨请求脏状态）需付费。仓库自带 Suricata / Sigma / ModSecurity 检测规则。修在 8.2.35 / 8.3.36 / 8.4.27 / 8.5.12。

能否结合当前 agent 实际

直接进你的 CTF 与 Web 攻防线，而且是「本周最该知道的一个洞」——它不需要应用有漏洞，PHP 默认配置就可能被打。

如何优化当前 agent 任务处理

三步落地。① 当靶场跑一遍四条 verify 脚本，把输出整理成 WP，重点写清 D/E 两条链为什么对「任何 endpoint」都成立（rfc1867 处理器在应用代码之前执行）。② 把检测规则段落抄成一份排查清单：查 PHP 版本、查 session.upload_progress 是否可达、查 FPM 的 serializer 配置——以后接到「帮我看看这个站」的活，先跑三分钟清单。③ 给它写一个 make lab 目标串起起靶场和四条验证，下次重跑只花一条命令。

🧨
9bie/php2shell-bypass-aslr-exp

在完全官方配置下打通 php2shell：不改 memory_limit、不开 display_errors、目标只有一行 echo，10/10 成功。

Python ★ 1.4k
能怎么用

约束很硬：官方 prefork 的 MaxRequestWorkers=150、官方 ini、官方镜像；目标页只有 <?php echo "OK\n"; ?>，全程只走 HTTP。手法是先占住 149 个 worker 的未完成请求，再把 A1/B1/A2/B2 固定到剩下的同一个 child 上，单次 3–4 秒。单 worker 版本是早期调试形态，--workers 1 仍可复现。

能否结合当前 agent 实际

补上了 ikow 那篇「实验室环境」和「生产默认配置」之间的差距——这正是写 WP 时最缺的一节：为什么在真实环境也打得通。

如何优化当前 agent 任务处理

它的核心技巧是「把资源池耗干当同步点」：占满 worker 之后，后续请求必然落到同一个进程。这个方法可以搬到你其他的并发类脚本上——限速下的暴力枚举、竞态窗口利用、需要「保证同进程」的内存马投递，都可以用「先耗尽再复用」替代死等。把这套写法整理成一个可复用模块，比每次重写 sleep 靠谱。
